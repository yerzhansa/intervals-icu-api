# Intervals.icu API 0.2.0 investigation matrix

Date: 2026-08-06  
Status: Complete  
Scope: Sanitized contract investigation for `0.2.0`; no athlete identifiers, credentials, dates, or sample values are retained.

## Executive result

The `0.1.2` resource API already returns deeply camel-cased values at runtime, but several declarations describe the upstream wire casing. Operational fetch and parsing failures can also reject instead of returning `Result`. Both defects are reproducible. The official schema has moved forward additively, and activity streams require a handwritten overlay because their OpenAPI model describes array data only as `object`.

The accepted release boundary is:

- correct existing resource response declarations without changing their runtime shape;
- preserve upstream casing for request DTOs, generated OpenAPI types, decoders, and `client.raw`;
- normalize operational failures for managed resource calls;
- add typed, extensible streams and `getIntervals()`;
- add download metadata without changing existing byte/string return values;
- refresh the checked-in schema and make regeneration and drift reporting reproducible;
- defer curves, histograms, best efforts, power-versus-HR, and recursive casing redesign to `0.3.0`.

## Endpoint and behavior matrix

| Surface | `0.1.2` observation | Official/live observation | `0.2.0` contract |
|---|---|---|---|
| Convenience JSON responses | Runtime keys are deeply camelCase; declarations often remain snake_case | Existing live fixtures match camelCase transformation | Return and declare camelCase |
| Request bodies | Generated upstream DTO casing | Mixed upstream wire conventions | Preserve wire casing in `0.2.0` |
| Generated types | `paths`, `components`, and `operations` expose wire shapes | Required for full OpenAPI escape hatch | Preserve and add explicit `Wire*` aliases |
| Decoders | Validate and return wire objects without transformation | README implied camelCase incorrectly | Preserve wire behavior and document it |
| `client.raw` | Bare `openapi-fetch` client; tuple result; can reject | Bypasses limiter, retries, and hooks | Preserve tuple/types, route calls through limiter/retry/hooks, document that raw may reject |
| Network failure | Rejects with `TypeError` | Reproduced with failing fetch | Managed calls resolve `Network` |
| Timeout | Variant exists but is unreachable | No configured timeout | Add optional per-attempt `timeoutMs`; resolve `Timeout`; default remains no timeout |
| Abort | Can reject with `AbortError` | Reproduced | Managed calls resolve `Network` with an abort message; raw keeps dependency semantics |
| Malformed success JSON | Rejects with `SyntaxError` | Reproduced | Managed calls resolve `Validation` with a synthetic root issue |
| Schema-invalid JSON/`204` | Resolves `Validation`, but skips `onError` | Reproduced | Resolve `Validation`; call terminal `onError` exactly once |
| Non-JSON HTTP error | Usually resolves an HTTP variant | Plain-text `502` reproduced | Preserve body; never parse it as required JSON |
| `401`, `403`, `404` | Dedicated variants | Stable | Preserve variants and actual body |
| `429` | `retryAfterMs` hard-coded to 1000 | Header may be seconds or HTTP date | Parse header; use `0` when absent/invalid |
| `5xx` | Configured status retries | Retry is not method-aware | Preserve status retry behavior in `0.2.0`; do not add transport retries |
| Hooks | Validation/transport failures can skip `onError` | Reproduced | One `onRequest`; one `onRetry` per retry; one terminal `onResponse` or `onError` |
| Activity streams | `getStreams(id, string[])` returns `Result<unknown>` | Rows contain `type`, array `data`, optional paired `data2`, metadata, unknown/custom fields | Typed descriptor array; compatibility overload plus options overload |
| Streams: omitted `types` | Cannot be expressed by resource API | Returns the same defaults available for the sampled activity | Options are optional; omission stays omission, never coerced to `[]` |
| Streams: `includeDefaults` | Cannot be expressed | With explicit types, `true` adds default channels; `false` returns requested channels | Add boolean option |
| Streams: latitude/longitude | Untyped | Numeric latitude in `data`, longitude in `data2` | Both arrays retained |
| Intervals | No convenience method | Dedicated endpoint matches interval/group counts from full activity response | Add `getIntervals(id)` only as analysis-surface proof |
| FIT download | `ArrayBuffer` only | `application/octet-stream`; filename present | Preserve bytes; add metadata opt-in |
| GPX download | `ArrayBuffer` only | `application/gpx+xml`; filename present | Preserve bytes; add metadata opt-in |
| Original download | `ArrayBuffer` only | Octet-stream; filename present | Preserve bytes; add metadata opt-in |
| CSV export | `string` only | `text/csv`; filename present | Preserve string contract |
| Content encoding | Not exposed | Responses sampled with HTTP gzip; Fetch returns decoded bytes | Expose header as transport metadata; never decompress again |
| Workout ZIP | Sends no required query | Live endpoint returns `422`; `ext`, `oldest`, and `newest` are required | Add options; omitted options return local `Validation` without fetch |

## Schema provenance and drift

Canonical discovery chain:

1. Swagger UI initializer requests `https://intervals.icu/api/v1/docs/swagger-config`.
2. That configuration identifies `https://intervals.icu/api/v1/docs` as the live OpenAPI document.
3. A normalized checked-in `openapi.json` is the immutable generation input for a package release.

| Metric | Checked-in `0.1.2` | Live on 2026-08-06 |
|---|---:|---:|
| Paths | 113 | 117 |
| Operations | 143 | 148 |
| Schemas | 107 | 110 |

The observed drift is additive. Added paths are athlete listing, athlete groups, athlete connections, and activity tombstone deletion; an update-message operation was added to an existing chat path. Added schemas are `ActivityAnalysisIssue`, `AthleteWithTags`, and `AthleteConnections`. Activity, interval, and interval-group models gained running-dynamics fields.

Required CI uses only the checked-in snapshot. A scheduled/manual job may query upstream and emit a categorized Markdown diff; package builds must not depend on Intervals.icu availability.

## Stream contract

The official data-model documentation lists these known names:

`time`, `watts`, `cadence`, `heartrate`, `distance`, `altitude`, `latlng`, `velocity_smooth`, `moving`, `grade_smooth`, `temp`, `torque`, `fixed_watts`, `fixed_heartrate`, `left_right_balance`, `left_pedal_smoothness`, `right_pedal_smoothness`, `left_torque_effectiveness`, `right_torque_effectiveness`, `smo2`, `thb`, `smo2_2`, `thb_2`, `dfa_a1`, `epoc`, `hrv`, `ga_velocity`, `fixed_altitude`, `corrupt_time`, `core_temperature`, `skin_temperature`, `stride_length`, `w_bal`, `respiration`, `tidal_volume`, `tidal_volume_min`, `watts_alt`, `watts_alt_acc`, `bloodglucose`, and `artifacts`.

The list is autocomplete, not a closed enum: athlete-defined and future channels must remain valid. Standard sampled channels contained `number | null`; official documentation also permits boolean and other numeric representations. `data` and `data2` therefore use a generic/unknown element type by default. Unknown row fields are retained.

The streams endpoint also documents special power behavior: `fixed_watts` is returned as `watts`, while requesting `raw_watts` or omitting `types` may rename the stored watts stream to `raw_watts`.

## Compatibility evidence

- The repository is clean at tag `v0.1.2` before work begins.
- All 74 baseline tests pass on Node 24.
- The current development toolchain cannot start on Node 20.11 because it imports `node:util.styleText`; this is a contributor-tooling constraint, not evidence that the built runtime requires Node 22.
- Existing `cycling-coach` call sites use `getStreams(id, string[])` and reduce descriptor rows by `type`. The proposed overload and return type remain structurally compatible.
- Current download consumers expect `ArrayBuffer` and CSV consumers expect `string`; metadata is therefore additive and opt-in.
