# RFC-0001: intervals-icu-api 0.2.0 correctness contract

Status: Accepted for implementation  
Date: 2026-08-06  
Target: `0.2.0-beta.1`

## Decision summary

`0.2.0` has one objective:

> Make existing Intervals.icu capabilities type-safe, predictable, and backward-compatible.

This RFC accepts the investigation in `docs/v0.2-investigation-matrix.md` and closes its contract questions. Implementation proceeds as small, independently testable changes. Broad analytics conveniences remain `0.3.0` work.

## 1. Naming and raw-response policy

Convenience resource responses are canonically camelCase. This matches their existing runtime values and documented examples. Public response types are defined from explicit wire aliases through `CamelCaseKeys<TWire>`; transformed values must no longer be asserted as the wire type.

The following remain in upstream wire casing:

- checked-in OpenAPI and generated `paths`, `components`, and `operations`;
- request DTOs;
- standalone schema decoders;
- the raw client response.

`WirePaths`, `WireComponents`, and `WireOperations` aliases are added for clarity without removing existing exports. Domain schemas expose `*Wire` aliases; their existing decoder functions continue returning validated wire objects. Changing decoder runtime output or accepting dual-case request DTOs is outside this release.

Deep key transformation of arbitrary dictionaries is an acknowledged collision risk. Redesigning recursive casing would change established runtime behavior and is deferred to `0.3.0`.

## 2. Error contract

Managed resource operations resolve `Result`; operational failures do not reject.

Allowed throws are programmer-controlled surfaces:

- invalid constructor configuration;
- `unwrap()` on an error result;
- hook code internally (caught and warned by the hook dispatcher);
- legacy/raw-client behavior, which keeps the `openapi-fetch` contract.

Failure mapping is:

| Condition                                  | Variant                                           |
| ------------------------------------------ | ------------------------------------------------- |
| HTTP 401/403/404/429                       | Existing dedicated variant                        |
| Other non-success HTTP                     | `Http`, with actual status text and response body |
| Valid JSON violating a schema              | `Validation`                                      |
| Malformed success JSON                     | `Validation` with a synthetic root issue          |
| Client-configured per-attempt deadline     | `Timeout`                                         |
| DNS, connection, Fetch/body-stream failure | `Network`                                         |
| External/unknown abort                     | `Network` with a generic abort message            |
| Unclassified operational exception         | `Unknown`                                         |

`IntervalsClientOptions.timeoutMs` is optional and disabled when omitted, preserving existing behavior. When configured it applies per attempt and aborts the underlying Fetch. Transport failures are not newly retried in `0.2.0`; ambiguous write retries could duplicate mutations. Existing configured HTTP-status retry behavior remains for compatibility.

`Retry-After` accepts strict integer seconds or an HTTP date. A final `RateLimit` error keeps required `retryAfterMs`; invalid or absent headers produce `0`.

Hooks follow a logical-operation contract: one `onRequest`, one `onRetry` for each retry, and exactly one terminal `onResponse` or `onError`.

## 3. Stream contract

`ActivityStream<T = unknown>` is a handwritten, loose runtime type because the official OpenAPI schema models `data` and `data2` as generic objects even though the endpoint returns arrays.

Required fields are `type: string` and `data: T[]`. Nullable/optional metadata includes `name`, `data2`, `valueType`, `valueTypeIsArray`, `anomalies`, `custom`, and `allNull`. Unknown fields survive validation and transformation.

Known channel names are exported as a readonly autocomplete list and a union derived from that list. Every API accepts `string` as well, so custom and future channels remain type-safe without casts.

Two overloads are supported:

```ts
getStreams(activityId, types: readonly string[]): Promise<Result<ActivityStream[]>>;
getStreams(activityId, options?: GetStreamsOptions): Promise<Result<ActivityStream[]>>;
```

The array form is retained and documented as deprecated in favor of options. `types` omission is sent as omission. `includeDefaults` is forwarded exactly. Responses remain descriptor arrays and are not normalized into maps.

## 4. Schema ownership and generation

The canonical upstream URL is `https://intervals.icu/api/v1/docs`. The checked-in normalized `openapi.json` is the release build input.

Commands must provide:

- `schema:fetch`: explicitly fetch, validate, normalize, hash, and update the snapshot;
- `schema:generate`: generate declarations only from the checked-in snapshot;
- `schema:check`: regenerate and fail on a dirty generated file;
- `schema:upstream-diff`: fetch live schema and emit categorized Markdown drift.

Required CI never relies on the network copy. Upstream drift runs only on manual/scheduled CI and uploads or summarizes its report. Generation tool versions stay locked in `package-lock.json`.

## 5. Raw client compatibility

`client.raw` retains its generated `openapi-fetch` method signatures, wire casing, and `{ data, error, response }` result shape. It is not converted to `Result`, and may reject on transport or parsing errors.

Raw HTTP verb calls are wrapped internally so rate limiting, configured HTTP retries, and request/response/error hooks are no longer bypassed. This wrapper deliberately does not validate or camel-case raw data. The dependency result remains observable and source compatible.

Raw `use()`/`eject()` middleware registrations continue to affect convenience resources as they did when both surfaces shared one client. Raw hook paths are the schema templates, not resolved URLs containing athlete or activity identifiers. A configured per-attempt timeout surrounds the complete `openapi-fetch` operation, including middleware and response parsing, and aborts its request signal. The final transport or middleware `Response` identity is preserved. A `parseAs: "stream"` result retains the same deadline until its data stream is consumed or cancelled.

The inherited Intervals.icu authorization is stripped when a raw call supplies a request-local `baseUrl` on another origin. An explicit request-local authorization value is preserved, so intentional alternate-origin authentication remains possible without leaking the client default.

Documentation must distinguish managed resource operations from raw operations and must not claim universal no-throw behavior.

## 6. Downloads

Existing methods keep returning `Result<ArrayBuffer>` (or `Result<string>` for CSV). Metadata is opt-in through additive overloads using `{ includeMetadata: true }`.

`BinaryDownload` contains decoded `bytes` plus sanitized `filename`, `contentType`, `contentLength`, and `contentEncoding`. `contentEncoding` describes transport; Fetch may already have decoded the bytes. Filename suggestions strip path components, controls, bidirectional overrides, and cross-platform reserved characters/names. Manual URL identifiers are encoded as opaque path segments, and client base URLs are normalized before paths are appended.

FIT and GPX options also expose the documented `power` and `hr` query flags.

`workouts.downloadZip()` remains source-callable with no arguments, but missing required options resolves a local `Validation` result and makes no request. Valid options require `format`, `oldest`, and `newest`, and forward range/locale fields.

## 7. Backward-compatibility guarantee

`0.2.0` preserves:

- public resource and method names;
- existing accepted arguments, including the stream-array form;
- existing convenience runtime casing;
- request DTO wire casing;
- raw result shape and generated exports;
- no-option download byte/string values.

Correcting response declarations can make code that referenced snake_case properties fail compilation. Those properties were already absent at runtime; this is classified as a type-correctness fix and is called out in the migration guide.

Deprecations are documentation/type annotations only in `0.2.0`; removals require a later release.

## 8. Node.js and TypeScript support

Runtime support remains Node `>=18` for backward compatibility. Contributor/test tooling requires Node `>=22.12` because the current Vitest/Vite/Ox toolchain does. CI separates these claims:

- build, lint, and unit tests on Node 22.12+ and Node 24;
- install/import/runtime smoke tests of the packed artifact on Node 18, 20, 22, and 24;
- consumer declaration tests on TypeScript 5.4.5 and the repository version (5.9).

The floor is evidence-based: the exact packed artifact compiles with `skipLibCheck: false` on TypeScript 5.4.5, while 5.0.4 through 5.3.3 fail inside the existing `openapi-fetch` helper declarations. Because `0.1.2` already ships the same dependency versions, claiming 5.0 support would be inaccurate rather than backward-compatible.

If the packed runtime matrix disproves Node 18/20 support, the beta blocks; the engine range is not silently raised.

## 9. Exact release scope

Included in `0.2.0`:

- official schema refresh and deterministic generation/drift tools;
- camelCase response declaration correction;
- normalized managed errors and optional timeout;
- typed/extensible streams with compatibility overload;
- raw calls routed through rate/retry/hooks without changing raw results;
- additive download metadata and corrected ZIP query contract;
- `getIntervals()` as the single analysis-endpoint proof;
- unit, runtime, type-compatibility, package, migration, and changelog work.

Deferred to `0.3.0`:

- curves, histograms, best efforts, and power-versus-HR conveniences;
- normalized stream maps or analysis calculations;
- camelCase request DTO redesign;
- recursive-casing redesign;
- method-aware transport retry policy;
- a new Result-returning arbitrary-request surface.

## 10. Implementation and release sequence

1. Add sanitized fixtures and `0.1.2` consumer compile tests.
2. Refresh OpenAPI and add deterministic schema commands.
3. Correct the executor/error contract and hooks.
4. Align runtime and response declarations.
5. Add typed streams and the compatibility overload.
6. Wrap raw calls and add download metadata/ZIP options.
7. Add `getIntervals()`.
8. Update README, migration guide, changelog, CI, and package version.
9. Build and `npm pack`; install the tarball in an isolated `cycling-coach` canary.
10. Run sanitized live shape checks, then retain `0.2.0-beta.1` locally for maintainer review.

Publishing, pushing, opening PRs, and releasing stable `0.2.0` require separate explicit approval.

## 11. Release-candidate gates

The beta is blocked unless tests cover:

- timeout, abort, DNS/network rejection, malformed JSON, non-JSON error bodies, `204`, `429`, and `5xx`;
- retry/rate-limit/header parsing and exact hook behavior;
- unknown response fields and stream types;
- compile-time/runtime camelCase agreement;
- legacy raw, stream, and download consumer compatibility;
- binary metadata, malicious filenames, compressed transport, and body-read failure;
- `npm pack` installation and Node/TypeScript matrices;
- credential/sensitive-log scans;
- isolated `cycling-coach` typecheck/tests plus an ephemeral live shape canary.
